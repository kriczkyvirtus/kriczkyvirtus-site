## 2 · ✅ PROBABLY NOT A BUG — report clipping at 390px

> A refreshed 390px view shows visible right-side clipping.

**You identified this yourself earlier in the session:** the report's viewport hook reads `window.screen.width`, not `window.innerWidth`. A desktop browser resized to 390px still reports a 1920px screen, so the hook never fires and the 816px document overflows. Under true device emulation you tested it and it passed.

**But the hook is fragile, and that's worth fixing.** Apply this diff to `ReinvestHarvestReport.jsx`:

```diff
- const w = window.screen && window.screen.width ? window.screen.width : window.innerWidth;
+ /* Use whichever is smaller. screen.width alone misses resized desktop browsers;
+    innerWidth alone misreads some mobile browsers during orientation change. */
+ const sw = window.screen && window.screen.width ? window.screen.width : Infinity;
+ const w = Math.min(sw, window.innerWidth || Infinity);
```

Then retest at a 390px **viewport** — it should scale correctly without device emulation.

| `4155550138` | 415-555-0138 ✅ | — |
| `+1 415 555 0138` | **141-555-5013** ❌ | 415-555-0138 |
| `1-415-555-0138` | **141-555-5013** ❌ | 415-555-0138 |

The formatter strips non-digits then takes the first ten, so a leading country code shifts everything one place. Diff for `ReinvestHarvestFlow.jsx`:

```diff
  const fmtPhone = (v) => {
-   const d = v.replace(/\D/g, "").slice(0, 10);
+   let d = v.replace(/\D/g, "");
+   /* Drop a leading US country code — otherwise "+1 415…" shifts every digit
+      one place and produces 141-555-5013. */
+   if (d.length > 10 && d[0] === "1") d = d.slice(1);
+   d = d.slice(0, 10);
    if (d.length <= 3) return d;
```
